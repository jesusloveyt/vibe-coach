# Vive Coach

**AI와 대화하며 프로그램을 만들고, 결과를 확인하고, 원하는 방향으로 개선하는 경험을 돕는 학습 가이드입니다.**

코딩을 처음 접하는 분도 프롬프트를 입력하여 시작할 수 있습니다. 직접 내용을 바꾸거나, 코드가 조금씩 늘어나는 모습을 살펴보는 과정도 준비되어 있습니다. 완성된 결과물과 함께 **내 의도를 전달하고 AI가 만든 결과를 확인하는 힘**을 기르는 것이 목표입니다.

**[처음 시작하기](./starter/README.md) · [도구 설치하기](./setup/README.md) · [개발자로 기여하기](./community/CONTRIBUTING.md)**

## 어떤 경험을 해 보고 싶으세요?

| 과정 | 만드는 것 | 학습자가 하는 일 | 시작하기 |
| --- | --- | --- | --- |
| **Starter** | 계산기 또는 자기 소개 웹사이트 | AI에게 요청하고, 결과를 열어 보고, 수정할 점을 말합니다. | [Starter 안내](./starter/README.md) |
| **Calculator** | 사칙 연산 계산기 | 버튼의 `?`를 숫자로 직접 바꾸고 검토받습니다. 원하면 계산 로직도 수정합니다. | [Calculator 안내](./solutions/calculator/README.md) |
| **Resume** | 이력서 웹페이지 | 내용을 한 장씩 제공하고, 추가·변경되는 코드와 화면을 확인하며 질문합니다. | [Resume 안내](./solutions/resume/README.md) |

**첫 경험이라면 Starter를 권합니다.** AI가 코드를 작성하므로 문법을 공부하거나 코드를 직접 편집할 필요가 없습니다. 자료 없이 시작하고 싶다면 계산기를 선택하세요.

**직접 바꿔 보고 싶다면 Calculator를 선택하세요.** 숫자 표시 수정에서 시작해 저장 → 검토 → 실행 확인을 경험합니다. 선택형 로직 실습에서는 덧셈·뺄셈을 자세한 안내에 따라 수정하고, 곱셈·나눗셈은 직접 작성한 뒤 리뷰받습니다.

**만들어지는 과정을 보고 싶다면 Resume를 선택하세요.** 기본 정보, 학력, 경력, 특기 및 장점, 주요 경험을 단계적으로 입력하거나 이미지·PDF로 제공합니다. 자기소개는 앞서 정리한 내용을 바탕으로 AI가 추천하고, 확인 후 반영합니다. 완성한 이력서를 개인 PR 페이지로 발전시키는 예시도 있습니다.

과정을 모두 순서대로 수료할 필요는 없습니다. `starter/`는 공통 입문 과정이며, `solutions/`에는 주제별로 서로 다른 학습 경험을 모읍니다.

## 시작하는 방법

1. **도구를 준비합니다.** [설치와 계정 연결 안내](./setup/README.md)를 따라 VS Code와 파일을 만들고 수정할 수 있는 AI 도구를 준비하세요. Codex와 Claude Code 중 하나를 선택할 수 있습니다.
2. **과정의 README를 엽니다.** 위 표에서 원하는 과정을 선택하고, 안내에 따라 해당 과정의 AGENTS.md를 연습 폴더에 준비합니다.
3. **시작 프롬프트를 보냅니다.** 과정에 적힌 요청을 AI에게 전달하고, 안내에 따라 만들기와 확인을 진행합니다.

이미 VS Code에서 AI와 대화할 수 있다면 설치 단계는 건너뛰어도 됩니다. 현재 제공하는 기본 실습은 저장소를 복제하거나 GitHub 계정, Node.js, 데이터베이스를 준비하지 않아도 시작할 수 있습니다.

**AGENTS.md는 코딩 AI 에이전트가 읽고 따르는 코칭 지침입니다. 학습자가 직접 읽거나 외워야 하는 안내서는 아닙니다.** 학습자는 README를 따라 파일을 준비하고 AI에게 읽도록 요청하면 됩니다. 기여자는 AGENTS.md를 작성·검토하며 코칭 방식을 개선합니다.

AI는 연습 폴더의 `codes` 아래에 결과물을 만듭니다. 실제 파일 위치는 AI의 안내를 확인하세요. 브라우저에서 열고, 수정 후 새로고침하면 변화가 보입니다. 기본 실습만으로 결과물이 인터넷에 게시되지는 않습니다.

## 대화하면서 함께 배웁니다

모든 과정의 중심은 **요청하기 → 결과 확인하기 → 수정 요청하기**입니다. AI도 요청을 잘못 이해하거나 실수할 수 있으니, 예상과 다른 결과는 그대로 알려 주세요.

- 설명이 어렵다면: “더 쉽게, 지금 할 일 하나만 알려 줘.”
- 화면이 다르다면: “말한 화면과 달라. 현재 파일을 확인해 줘.”
- 코드가 궁금하다면: “추가한 코드가 화면의 어느 부분을 만드는지 설명해 줘.”

AI는 필요할 때 더 명확하게 요청하는 표현도 짧게 제안합니다. 처음부터 완벽한 프롬프트를 작성할 필요는 없습니다. Resume에서는 코드가 바뀔 때마다 확인할 부분을 안내하고, 질문할 기회를 제공합니다.

도구 준비에 도움이 필요하면 [공통 설치 안내](./setup/README.md), [Codex 안내](./setup/codex.md), [Claude Code 안내](./setup/claude-code.md)를 참고하세요. 이용 요금과 사용량 제한은 사용하는 서비스에 따라 다르므로 준비 안내의 비용 설명도 확인해 주세요.

## 개발자 여러분, 새로운 학습 과정을 만들어 주세요

**프로그램을 개발하고 문제를 해결해 본 여러분의 경험이 필요합니다. 초보자가 AI와 함께 따라갈 수 있는 과정을 만들어 `solutions/`에 추가해 주세요.**

기여의 핵심은 무엇을 요청하고, 어떤 순서로 만들고, 어디서 결과를 확인할지 담은 **학습 안내와 AI 코칭 지침**입니다. 일상 도구, 단계별 기능 확장, 데이터 저장이나 외부 서비스 연동 등 다양한 주제를 환영합니다.

### 문서마다 독자가 다릅니다

| 문서 | 독자와 역할 |
| --- | --- |
| `README.md` | **학습자**를 위한 목표, 준비 사항, 시작과 실행 안내 |
| `AGENTS.md` | **코딩 AI 에이전트**가 따를 단계별 행동, 기다릴 시점, 오류 대응과 코칭 지침 |
| `dialogues.md` | **학습 경험을 살펴볼 사람**을 위한 대표 대화. 실습 후 추가할 수 있습니다. |
| `maintainer-notes.md` | **다음 기여자**를 위한 제작·개선 노트. 아이디어, 결정 이유, 메모, 이슈와 검증 결과를 담습니다. |

학습에 꼭 필요한 확정 내용은 README나 AGENTS에 반영하고, 제작·개선 노트에는 판단의 배경과 남은 과제를 기록합니다. 실습에서 생성한 프로그램 코드 파일은 제출하지 않으며, 코드 조각과 필요한 결과 이미지는 안내 문서에 포함할 수 있습니다.

### 작은 초안부터 참여하세요

1. `solutions/<주제명>/`에 학습 목표를 정하고 README.md와 AGENTS.md를 작성합니다. **대화 예시 없이도 초안 PR을 제출할 수 있습니다.**
2. 주제별 실습 채팅에서 학습자처럼 진행합니다. 개발 지식으로 개입해야 했다면 제작·개선 노트에 기록하고 필요한 지침을 보완합니다.
3. 새 채팅과 별도 연습 환경에서 수정된 안내를 검증합니다. 확인한 범위와 남은 문제를 표시하고, 준비된 대화 예시를 추가합니다.
4. 학습 대상, 변경 내용, 실제 확인한 결과를 적어 Pull Request를 보내 주세요. 관리자가 검토한 뒤 반영합니다.

메인·기획 채팅, 주제별 실습 채팅, 조정·문제 해결 채팅을 구분하면 학습 안내에 빠진 내용을 발견하기 쉽습니다. 새 채팅에서도 기존 파일이나 지침의 영향이 남을 수 있으므로 검증 환경을 함께 기록해 주세요.

**[기여 가이드에서 제작 흐름과 기록 양식 보기](./community/CONTRIBUTING.md)**

기여 가이드에는 채팅방 운영, 대화 예시 편집, 지침 버전 관리와 준비 상태 표시 방법을 정리했습니다. 새 주제 제안은 Issue로 논의할 수 있으며, 기존 안내의 오류 수정과 학습 중 막힌 부분의 보고도 환영합니다.
